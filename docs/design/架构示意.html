① 导航架构（NavHost 路由图）

底部 3 个 Tab（Scaffold + NavigationBar）；添加/编辑为全屏子路由（无底部栏）；校准是独立路由，由保活页跳转进入，不是页内浮层。startDestination = contacts。

关键事实：calibration 在代码里是 composable(Routes.CALIBRATION) 的独立全屏路由，由 KeepAliveScreen.onNavigateToCalibration 跳转。当前 v2 预览把它做成了页内 8 步浮层，这与架构不符，需改为独立页面。

② 路由清单（object Routes）

来自 ui/navigation/AppNavigation.kt 的真实定义。

常量Route类型底部栏入口
CONTACTScontacts主 Tab显示启动默认
CONTACTS_ADDcontacts/add全屏子页隐藏联系人页「+」
CONTACTS_EDITcontacts/edit/{id}全屏子页隐藏联系人卡片编辑
KEEP_ALIVEkeepalive主 Tab显示底部 Tab
ABOUTabout主 Tab显示底部 Tab
CALIBRATIONcalibration独立路由隐藏保活页按钮跳转
底部栏可见条件：currentRoute in {contacts, keepalive, about}。从 CallBridge 跳转（navigate_to_calibration）会经 MainActivity 把 initialRoute 设为 calibration。

④ 桌面快捷方式 → CallBridge → 微信 流程

固定图标采用回调式确认；点击图标经透明桥接 Activity 校验后拉起微信无障碍服务。来自 shortcut/ShortcutHelper.kt、bridge/CallBridgeActivity.kt。

「禁止直接标记已固定」规则已落实：仅 ShortcutResultReceiver 确认放置后，才通过 onPinConfirmed 把 shortcut_pinned 写回 Room。
